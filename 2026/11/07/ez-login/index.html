解题步骤

第一步：绕过 no session 检查

原理：PHP 的 PHP_SESSION_UPLOAD_PROGRESS 机制——在文件上传时，PHP 会自动初始化 session 并在 session 中存储上传进度信息，即使代码没有调用 session_start()。

触发条件：

  • session.use_strict_mode=off（PHP 默认值）
  • 必须是 POST 请求，Content-Type 为 multipart/form-data
  • 请求中包含 PHP_SESSION_UPLOAD_PROGRESS 字段和文件字段

第二步：绕过 check_inner_ip

通过对 check_inner_ip 函数进行黑盒测试，分析其行为：

URL 格式 返回结果 说明
空字符串 http or https accepts (21字节) 协议不合法，函数直接输出提示
http://127.0.0.1/ Your IP is internal yoyoyo 内网 IP 被拦截
http://0.0.0.0/ Your IP is internal yoyoyo 被拦截
http://example.com/ Your IP is internal yoyoyo 被拦截
http://2130706433/ (十进制) 回显源码 DNS 解析失败，触发异常绕过
http://0x7f000001/ (十六进制) 回显源码 DNS 解析失败
http://localhost/ SSRF 成功执行 绕过成功

结论：check_inner_ip 很可能是基于 gethostbyname() 解析后判断是否为内网 IP 段（127.x.x.x、10.x.x.x 等），而 localhost 被 gethostbyname 解析后不会被判定为内网 IP（或绕过了正则匹配），但 curl 能正确将其解析为 127.0.0.1 进行请求。

漏洞链总结

知识点梳理

  1. PHP_SESSION_UPLOAD_PROGRESS：PHP 文件上传时自动初始化 session 的机制，可绕过无 session_start() 的 session 检查。这是 PHP < 8.0 中一个常被忽视的 session 初始化入口。
  2. SSRF 绕过 IP 限制：localhost 可绕过基于 gethostbyname + 内网 IP 段判断的检查函数，因为 localhost 在某些实现中不被解析为 127.0.0.1（或正则未覆盖）。
  3. check_inner_ip 黑盒测试方法：通过构造不同格式的 URL（IP 十进制、十六进制、域名等）观察返回结果差异，推断函数的检测逻辑。
  4. SQL 双引号闭合盲注：当 SQL 语句用双引号拼接且无过滤时，可直接构造 " 闭合 + or 条件的盲注 payload。
  5. HTML 注释信息泄露：开发者在 HTML 注释中留下的源码路径线索，属于常见的信息泄露类型。
  6. curl FOLLOWLOCATION：CURLOPT_FOLLOWLOCATION=1 会跟随 302 重定向，在 SSRF 中可能被利用来扩大攻击面。
